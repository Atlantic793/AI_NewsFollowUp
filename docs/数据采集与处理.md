# 数据采集与处理

日期：2026-11-08。本文按当前代码写成，代码改了这里跟着改。

页面怎么排见 [项目重构建议.txt](../项目重构建议.txt)，地址从哪来见 [大模型厂商官方信息源.md](../大模型厂商官方信息源.md)。

链路分四步，每一步的结果都记在采集页上：

1. **抓取**：请求登记的地址，把原始响应整份存盘。
2. **抽取**：按这一页专门的解析规则，摘出候选行和它在原文里的那一段。
3. **清洗**：归一字段、校验必填项、去掉导航文字、去重。丢掉的行要写明原因。
4. **入库**：用这一轮的行替换这个来源上一轮的行，并和上一轮比出变化。

## 1. 原则

- 只抓官网、官方文档或官方数据接口，第三方转述的数字不用来补空。OpenRouter 等聚合站不抓。
- 遵守 robots.txt（RFC 9309）。不绕过登录，不改地区，不用搜索引擎缓存代替原页。
- 一栏只收这一栏的行：价目不收新闻，动态不收价格。菜单、登录、页脚、Copy page、目录都不是数据。
- 页面里找不到这一栏要的行，就记「没抽出」，并清空这个来源的旧行。不拿页面上别的文字凑数。
- 每一行都带 `excerpt`，即它在原始响应里的那一段，栏目页右栏只显示这一段。

## 3. 抓取

一轮按登记顺序逐个来源跑（`runLedger`）：

1. 来源需要 Kaggle 凭据而 `.env` 没配，记 `skipped`。
2. 每个网站读一次 `robots.txt`：
   - 先看 `ai_newsfollowup` 组，没有再看 `*`；
   - 支持 `*` 和 `$`，最长规则胜出，同长时 Allow 胜出；
   - robots.txt 返回 404 之类，视为不限制；返回 5xx 或连不上，这一轮不抓。
   - 不允许抓的路径记 `skipped`。
3. 同一网站两次请求至少隔 2 秒。
4. User-Agent 为 `AI_NewsFollowUp/0.2 (course data-collection project)`，超时 30 秒，跟随重定向。最后跳到别的网站就记失败。
5. 状态码出错时：
   - 401、403 记「网站拒绝访问，不绕过」；
   - 404 记「地址不存在了」；
   - 429 记「请求太频繁」。
6. 原始响应整份写到 `<数据目录>/raw/<日期>/<编号>.<html|md|json|xml>`，同时记字节数和 sha256。

数据目录默认是 `%APPDATA%\AI_NewsFollowUp`，可以用环境变量 `FOLLOWUP_DATA_DIR` 改。

## 4. 抽取

`extract(source, body)` 按来源登记的 `parser` 分派，规则见第 2 节。抽取只照原样摘字段（`PriceDraft`、`RankDraft`、`HotDraft`、`EventDraft`），不做归一。每条都带 `excerpt`。

页面结构对不上导致解析抛错时，记「没抽出」，原因写「解析失败：…」。

## 5. 清洗

`clean(source, extracted, today)` 按栏目处理。丢掉的每一条都带原因，并按原因计数。

| 栏目 | 必填与校验 | 归一 | 只留 |
| --- | --- | --- | --- |
| 价目 | 产品名、计价项、价格（套餐可以只有额度） | 价格解析出数额、币种、展示值（`$2.50`、`¥12`），括号里的说明并入条件；单位统一为「每百万 token」「每月」「每席位每月」等；Standard/Batch 改成标准/批量 | 全部 |
| 排名 | 名次是正整数、模型名、分数是数字 | 榜单日期转成 YYYY-MM-DD | 每榜前 50 |
| 热榜 | 标题、条目自己的链接，链接要在榜单网站上；GitHub 和 Hugging Face 的标题必须是 owner/name | 名次按清洗后的顺序重排 | 每源前 25 |
| 动态 | 标题、日期（状态行没有日期就用当天）；状态行要有状态 | 状态词译成中文（operational → 正常 等）；日期转成 YYYY-MM-DD | 每源最近 20 条，状态行全留 |

每一栏都会做的检查：

- **导航词**：标题或产品名正好是 Sign in、Pricing、Copy page、登录、首页这类词，就丢掉，原因「导航或按钮文字」。状态行的组件名不做这项检查，因为状态页上本来就有叫 Login 的组件。
- **去重键**：
  - 价目：产品 + 档位 + 计价项 + 条件；
  - 排名：模型；
  - 热榜：链接；
  - 动态：类型 + 标题 + 日期；状态行用组件 + 链接。
  - 键相同、值也相同，记「重复」；键相同、值不同，记「同一项出现两个不同的值，留第一处」。
- **中国大陆**：只有同一句里既写到中国大陆（或中国内地），又写到注册、调用或付款，这一行才标成 `cn_access`。

常见的丢弃原因：

| 原因 | 什么时候出现 |
| --- | --- |
| 格子是空的 | 价目表里这一格是空的或只有 — |
| 这一档不提供 | 格子写着 Not available |
| 要联系销售，没有标价 | 格子写着 Contact sales |
| 不是价格 | 格子里没有数字 |
| 没有币种 | 有数字，但页面和表头都没写币种 |
| 页面没有标价 | 套餐既没有价格也没有额度 |
| 名次不是数字 | 排名行的名次读不出 |
| 分数不是数字 | 排名行的分数读不出 |
| 没有模型名 | 排名行缺模型名 |
| 没有标题 | 热榜或动态行缺标题 |
| 没有日期 | 非状态的动态行缺日期 |
| 没有状态 | 状态行缺状态 |
| 没有自己的链接 | 热榜行没有条目链接 |
| 链接不在榜单网站上 | 热榜行的链接指向别的网站 |
| 不是 owner/name 形式的条目 | GitHub、Hugging Face 的标题格式不对 |
| 导航或按钮文字 | 见上面的导航词检查 |
| 重复、同一项出现两个不同的值 | 见上面的去重键 |
| 只留前 N 名、只留最近 N 条 | 超出这一栏保留的条数 |

## 6. 没抽出

下面两种情况，这个来源都记「没抽出」，并清空它在库里的旧行：

- 抽取一条都没摘到，原因写「页面里没有找到这一栏要的表或条目」；
- 摘到了，但清洗后一条不剩，原因写「抽到 N 条，全部没通过清洗」。

栏目页左栏显示这个来源的状态，中栏提示「这个来源这一轮没抽出」，不显示旧数据。

## 7. 入库与变化

库文件是 `<数据目录>/headline.sqlite`（`node:sqlite`），表结构版本记在 `PRAGMA user_version`。

| 表 | 一行是 |
| --- | --- |
| `sources` | 一个来源是否启用 |
| `runs` | 一次抓取。字段：`source_id`、`started_at`、`status`（ok / 没抽出 / skipped / failed）、`http_status`、`error`、`bytes`、`content_hash`、`raw_path`、`extracted`、`cleaned`、`stored`、`changed`、`rejected`，以及按原因计数的 `reasons`（JSON） |
| `rejects` | 最近一轮每个原因最多 3 条被丢弃的原文样例 |
| `prices` | 价目表里的一格：kind、product、tier、metric、condition、price、amount、currency、unit、quota、reset_rule |
| `ranks` | 榜上一行：rank_no、model、org、score、score_value、votes、board_date |
| `hot` | 热榜一条：rank_no、title、url、heat、summary |
| `events` | 一次发布、一条新闻或一个状态：type（release / news / status / incident / cn_access）、title、date、detail、url |
| `diffs` | 一处变化：source_id、column_kind、row_key、label、field、old_value、new_value |
| `watches`、`settings` | 定制名单、推送开关 |

`prices`、`ranks`、`hot`、`events` 四张表的每一行都带 `source_id`、`fetched_at`、`excerpt`。

同一来源入库是一次事务：先删旧行，再写新行。和上一轮比较时：

- 第一轮只建基线，不记变化。
- 价目比价格、单位、额度、重置；排名比名次、分数；热榜比名次；动态只比状态行的状态。
- 新出现的键记为「新增」；价目和排名里消失的键记为「掉出」。热榜和动态天天换，不记掉出。

定制页拿名单里的名字去匹配价目、排名、动态和变化表，不另外抓取。

## 8. 页面上看到什么

- **栏目页**（`/columns/:kind`）
  - 左栏：这一栏的来源，带行数或状态。
  - 中栏：清洗后的表，可以搜索。价目可按 API / 套餐筛，动态可按类型筛。
  - 右栏：只显示选中那一行的原文片段、原页面链接和抓取时间。
- **采集页**（`/collect`）
  - 列表：每个来源一行，列出抓取（HTTP 状态、大小）、抽取条数、清洗后条数、丢弃条数、入库条数、变化处数、结果和时间。
  - 右栏：四步逐条说明；丢弃原因展开后可以看样例；可以只重跑这一页、停用这个来源、看原始响应、看入库的行。

## 9. 已知限制

- OpenAI 状态 JSON 里有两个都叫 Login 的组件，且都没有分组。用组件 id 区分，表格里会出现两行 Login。
- GLM Coding Plan 文档没有写价格，只记额度和重置。
- Artificial Analysis 页面上没有印榜单日期，所以榜单日期留空。SWE-bench 的名次是按 % resolved 排出来的，榜单日期取榜上最新的提交日期。
- 状态行的日期：OpenAI 用组件的 `updated_at`，Claude 状态页 HTML 没有日期，用抓取当天。
- 「今天」按 UTC 日期算。
