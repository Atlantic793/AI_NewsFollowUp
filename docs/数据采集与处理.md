# 数据采集与处理

日期：2026-11-08。

本文规定 headline-chaser 抓哪些地址、怎样留下原文、怎样洗成表、怎样和上一份比较。页面怎么排见 [项目重构建议.txt](../项目重构建议.txt)。地址从哪来见 [大模型厂商官方信息源.md](../大模型厂商官方信息源.md)。

大作业要看到的是采集本身：多官网、页面不一样、失败要留原因、数字要能对回原文。OpenRouter 的模型目录不抓。

## 1. 沿用什么，改掉什么

沿用现在服务里已经有的打开方式：

- 已知链接才打开。先看本机能不能 GET 到正文。配了 `FIRECRAWL_API_KEY` 时，只用 Firecrawl 的单页抓取拿 Markdown，不用它的搜索、整站爬取和代理。
- 正文摘录有上限。现在是 3500 字，价目页和榜单页常常更长，这两类放宽到单页 2 万字，仍然只存这一页。
- 抓不到就空着。不用另一家网站的数字填上。
- 原始内容落在本地，不进 git。

改掉的是主路径。价目、排名、热榜、官网动态不再靠「主题检索词去各平台搜」。那些页面地址是固定的，搜标题会把转述和官网混在一起。社交媒体上的讨论不进第一版采集。厂商动态先只抓更新日志、新闻稿和状态页。

## 2. 四类数据

| 类 | 抓什么 | 不抓什么 |
| --- | --- | --- |
| 价目 | 官网 API 定价表、官方订阅和 coding plan 上写明的价格、额度、重置周期 | 转售价、代充、OpenRouter 路由价、控制台里要登录才看得到的账单 |
| 排名 | LMArena 文本榜、SWE-bench Verified、Artificial Analysis 的 Intelligence Index | 自己算的综合分、按 token 用量排的榜 |
| 热榜 | GitHub Trending、Hugging Face 模型趋势、Kaggle 竞赛列表 | 登录后的推荐流 |
| 动态 | 更新日志、官方新闻、状态页、模型卡上写明的能力字段；中国大陆是否能注册、调用、付款，只在原文出现时摘 | 其他国家的政策、页面没写就推断「已经恢复」 |

厂商首页、开放平台首页、要登录的控制台只当导航，写在信息源文档里，不进抓取队列。

## 4. 一次抓取怎么做

每一行源有固定字段：`id`、`vendor`、`kind`、`url`、`enabled`。`kind` 只允许 `api_price`、`plan`、`changelog`、`news`、`status`、`model_card`、`leaderboard`、`hotlist`。

一轮的顺序：

1. 读源清单。`enabled` 为假，或 `kind` 缺失，跳过。
2. 对主机请求 `robots.txt`。Disallow 覆盖该路径，就记 `skipped`，原因写 robots，不请求正文。
3. 同一主机连续请求至少隔 2 秒。一轮里每个 `url` 只请求一次。
4. 超时 20 秒。跟随重定向，但最终主机必须仍是登记时的那家，跳到别的厂商域名就记失败。
5. 保存原始正文、HTTP 状态、最终 URL、抓取时间、内容哈希。
6. 正文为空、是登录墙、或是地区不可用提示：记失败或 `blocked`。不换源重试。
7. 从正文抽表。抽不到的字段留空。
8. 和上一份成功快照做差分。

User-Agent 使用 `AI_NewsFollowUp`。不绕过登录，不改地区，不使用搜索引擎缓存代替官网。

运行记录每一行是：`source_id`、`started_at`、`status`（`ok`、`failed`、`skipped`、`blocked`）、`http_status`、`error`、`bytes`、`content_hash`。这就是采集页中栏。

## 5. 洗成四张表

抽取先用规则：表头、货币符号、`/1M`、名次列、changelog 的版本标题。规则拿不到的格子，才把这一页摘录交给模型，让它按下面的字段填。模型写出的数字、名次、日期，必须能在该页摘录里逐字找到，否则丢掉该字段。模型不补「合理的价格」。

### 5.1 价目 `prices`

一行是一个计费项或一个套餐档。

| 字段 | 含义 |
| --- | --- |
| vendor | 厂商 |
| product | 模型名或套餐名 |
| kind | `api` 或 `plan` |
| metric | `input`、`output`、`cache_read`、`cache_write`、`batch_input`、`batch_output`、`seat`、`quota` |
| price | 页面上的数字和货币，原样保存 |
| unit | 例如每百万 token、每月 |
| quota | 额度原文，没有就空 |
| reset | 重置周期原文，没有就空 |
| source_id | 对应 Pxx |
| url | 最终 URL |
| fetched_at | 抓取时间 |
| excerpt | 支撑这一行的原文片段 |

差分键：`vendor + product + kind + metric`。价格、额度或重置周期有一个不同，就产生一条变化：旧值、新值、`fetched_at`。

### 5.2 排名 `ranks`

| 字段 | 含义 |
| --- | --- |
| board | `lmarena_text`、`swebench_verified`、`artificial_analysis` |
| rank | 名次 |
| model | 榜上的模型名，不自行合并别名 |
| score | 榜上的分数原文 |
| board_date | 榜自己写的日期，没有就空 |
| source_id | Rxx |
| url | 最终 URL |
| fetched_at | 抓取时间 |
| excerpt | 这一行在榜上的原文 |

差分键：`board + model`。名次或分数变了才记变化。三张榜永远分开，不写综合名次。

### 5.3 热榜 `hot`

| 字段 | 含义 |
| --- | --- |
| source | `github`、`huggingface`、`kaggle` |
| rank | 名次，页面没有就空 |
| title | 标题 |
| url | 条目自己的链接 |
| fetched_at | 抓取时间 |

差分键：`source + url`。新出现的 url 记为新增。昨天有、今天没有，记为掉出，不删除历史。

### 5.4 动态 `events`

| 字段 | 含义 |
| --- | --- |
| vendor | 厂商 |
| type | `release`、`status`、`capability`、`cn_access` |
| basis | `official` 或 `unverified` |
| text | 一句原文，不超过摘录范围 |
| source_id | Nxx |
| url | 最终 URL |
| fetched_at | 抓取时间 |

`cn_access` 只在摘录同时提到中国大陆（或中国内地）以及注册、调用、付款、可用、不可用之一时生成。不从「部分地区不可用」推断就是中国大陆。

第一版 `basis` 全部是 `official`，因为队列里没有社交源。以后若加入讨论页，没有官网原句的条目用 `unverified`，文案是「尚无官网依据」。同一厂商、同一件事后来出现官网 URL，把 `unverified` 行并到那条 `official` 上，不再单独占一条。

能力字段只摘模型卡或更新日志里的原句，例如上下文长度、能否看图、能否调用工具。不写「更适合编程」。

## 6. 文件

提交用的数据集是一个 SQLite 文件：`data/headline.sqlite`。

表：`sources`、`runs`、`raw_pages`、`prices`、`ranks`、`hot`、`events`、`diffs`。

`raw_pages` 存正文和哈希。正文同时在 `data/raw/年-月-日/source_id.txt` 留一份，方便打开对数字。`diffs` 的一行是：表名、键、字段、旧值、新值、`fetched_at`。

这些文件不提交到 git。使用说明里写如何跑一轮之后在本地生成它们。

定制页不另建表。它只是用一份本地名单（模型名或套餐名）去过滤 `diffs`。过滤不到，就显示今天没有新变化。首页读各表最新一份，不用这份名单。

## 7. 和旧采集的界线

OpenCLI 搜索、主题检索词、热点四阶段，不参与价目、排名、热榜和官网动态。

Firecrawl 只在本机 GET 拿不到正文时，对队列里的这一个 URL 做单页抓取。密钥仍然只放在 `.env`，不进仓库，不写进抓取日志。

3500 字上限继续用于将来的讨论页摘录。价目和榜单使用第 1 节的 2 万字上限，避免表格被截断后抽出半行价格。
