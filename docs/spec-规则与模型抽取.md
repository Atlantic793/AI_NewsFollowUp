# SPEC: 规则与 DeepSeek 结合的四栏抽取

> 来源：已确认的下一阶段目标（本对话，无独立 PRD 文件）
> 日期：2026-11-21 | 分支：`main` | 提交：`5c74ea7`
> 旧文件 `旧项目文档/prd-topic-followup.md` 不属于本规格。

## 1. 摘要

### 1.1 范围

在现有「抓取 → 规则抽取 → 规则清洗 → 入库 → 差分」中加入 DeepSeek，分两层：

1. **字段以规则为准。** 价目表、榜单、热榜链接继续由规则抽取。只有整页抽不出合格行时，才把**这次抓到的原文**交给 DeepSeek 出候选。金额、分数、百分比、日期必须在该条候选的原文片段里逐字出现。
2. **模型只补看不清的部分。** 规则已经留下的行：厂商动态写一句中文；价目里表格没有填上的额度、重置、时段，从表格外的原文补进空字段。这一层不改已经核对过的价格、名次、分数和链接。

robots 拒绝、401/403、登录墙都不交给模型。这些轮次没有可核对的原文。页面不留空：有上一轮成功行就继续显示，并写明抓取时间和原因；从来没有成功行，就指向已经在抓的替代来源。

### 1.2 需求对应

| 编号 | 需求 |
| --- | --- |
| US-1 | 规则能抽出的表格、榜单、热榜链接保持现在的字段 |
| US-2 | 整页没有合格行时，用 DeepSeek 补候选，核对后才能入库 |
| US-3 | 模型失败、核对后仍为空、被 robots 拒绝或 403 时，不把栏目留空 |
| US-4 | 厂商动态打开就能看到一句中文；价目空着的额度、重置、时段被补上 |
| US-5 | 采集页能分开规则抽出、模型补抽、核对丢弃、本轮被拒绝 |
| FR-1 | 四栏字段含义不变，只增加给人看的 `brief` |
| FR-2 | 模型不改写已有价格和名次，不编造中国大陆政策，不绕过 robots 和 403 |
| FR-3 | 单元测试不访问真实 DeepSeek |

### 1.4 实现时为准确性改过的两处

- 价格在页面上按 1 美元 = 7.2 元换成人民币。库里的 `price`、`amount`、`currency` 仍是官网标价，差分也比官网标价。右侧原文保留官网金额。
- 介绍性字段优先用中文显示。动态标题和状态组件名保留原始名称，中文概括放在 `brief` 中；不能用「新闻，日期」或「正常」覆盖原始标题。原文片段不改写。

### 1.3 设计决定

| 决定 | 选择 | 理由 |
| --- | --- | --- |
| 接入点 | 扩展 `apps/server/src/ledger/run.ts` 的 `capture` | 抓取、robots、存盘、差分已经在这里 |
| 接口 | 现有 OpenAI 兼容体：`POST {OPENAI_BASE_URL}/chat/completions` | `.env` 使用 `OPENAI_BASE_URL=https://api.deepseek.com`、`OPENAI_MODEL=deepseek-chat`、`OPENAI_API_KEY` |
| 抽取触发 | 仅整页合格行为 0，且正文是 200 的正常文档 | 大表重抽会更慢，也更容易改数字 |
| 概括与补空 | 规则成功后仍做，但只写 `brief` 和原本为空的额度、重置、条件 | 直接提高清晰性；不触碰已核对字段 |
| 概括缓存 | 同一行的 `excerpt` 未变且已有模型 `brief` 时不再请求；规则降级概括不当作模型缓存 | 避免重复生成，同时允许密钥配置或模型恢复后重新概括 |
| 核对 | 纯函数放在 `packages/core`，位于模型输出之后、`clean()` 之前 | 测试不必联网 |
| 被拒绝的页面 | 不解析响应体，不调用模型；保留上次成功行 | 错误页和拒绝页没有可核对的价格 |
| 迁移 | 只 `ALTER TABLE` 加列。禁止因 `user_version` 较低而 `DROP` 现有表 | 当前 `store.ts` 在版本较低时会删表，实现时必须拿掉这条路径 |

## 2. 架构

### 2.1 顺序

```
robots / 凭据检查
    → 不允许、401、403：不取正文去抽取，保留旧行，结束
    → 200：存原始响应
        → 规则 extract + clean
        → 合格行为 0，且正文不像登录墙：DeepSeek 抽候选 → gate → 再 clean
        → 仍为 0：没抽出，旧行保留
        → 有行：只补空字段和 brief（excerpt 变了才调用模型）
        → replace，与上一轮差分（不比较 brief）
```

### 2.2 模块

| 模块 | 职责 |
| --- | --- |
| `packages/core/src/llm/gate.ts` | 丢弃片段不是原文子串、或数字对不上片段的候选 |
| `packages/core/src/llm/prompts.ts` | 四栏提示与 JSON 形状 |
| `apps/server/src/ledger/deepseek.ts` | 读环境变量、请求、超时；失败变成空结果，不抛出密钥 |
| `apps/server/src/ledger/assist.ts` | 决定补抽、补空、概括；跳过未变化的 excerpt |

`extract()`、`clean()` 的规则不改。页面上的 `POST /api/ledger/column/:kind/brief` 保留，直到表内 `brief` 上线后再决定是否去掉按钮。

### 2.3 文件

```
packages/core/src/llm/gate.ts       新增
packages/core/src/llm/prompts.ts    新增
packages/core/src/rows.ts           行增加 brief
packages/core/src/index.ts          导出 gate
apps/server/src/ledger/deepseek.ts  新增
apps/server/src/ledger/assist.ts    新增
apps/server/src/ledger/run.ts       拒绝页保留旧行；成功页才调用 assist
apps/server/src/ledger/store.ts     只 ALTER；写入 brief 与模型计数
apps/web 栏目页、采集页              显示旧行、原因、替代来源、brief
docs/数据采集与处理.md               与本规格对齐
```

## 3. 数据

### 3.1 新增列

四张行表各加 `brief TEXT NOT NULL DEFAULT ''`。

`runs` 加：

```sql
llm_drafts INTEGER NOT NULL DEFAULT 0
llm_kept INTEGER NOT NULL DEFAULT 0
llm_dropped INTEGER NOT NULL DEFAULT 0
```

规则路径这三项为 0。`llm_drafts` 是模型返回的候选数，`llm_kept` 是核对后并过了 `clean()` 的行数，`llm_dropped` 是核对丢掉的候选数。

### 3.2 什么参与差分

继续只比较现在已经比较的字段：价目的价格、单位、额度、重置；排名的名次和分数；热榜的名次；状态行的状态。`brief` 不参与比较。价格行用规则条件建立差分标识，模型补充的条件不制造新增或掉出。已核对的补充依据仍在当前正文中时，模型暂不可用不清空补充字段；原文哈希未变时不因补全覆盖率变化而记官网变化。正文变化时仍比较价格、额度和重置。

### 3.3 迁移

`user_version` 为 4，价格表增加内部 `comparison` 字段，保存规则条件、额度、重置与模型补全依据。版本较旧时不得删除 `prices`、`ranks`、`hot`、`events`、`diffs`、`runs`、`row_archive`。缺列时 `ALTER TABLE ... ADD COLUMN`。

## 4. 接口

不新增采集 URL。

`GET /api/ledger/sources` 的 `run` 增加 `llmDrafts`、`llmKept`、`llmDropped`。已有 `status`、`error`、`httpStatus` 足够表达 robots 和 403。

行对象增加 `brief`。栏目接口在来源本轮不是 `ok` 但仍有行时，增加：

```json
{ "stale": true, "staleReason": "HTTP 403：网站拒绝访问（要登录或地区受限），不绕过", "fetchedAt": "上次成功行的时间" }
```

`staleReason` 用该来源最近一次运行的 `error`。`fetchedAt` 用行上的时间，不用本轮失败时间。

## 5. 业务规则

### 5.1 DeepSeek 调用

- 无 `OPENAI_API_KEY`：不调用，行为与现在相同。
- `temperature: 0`，要求 JSON 对象。
- 超时 45 秒。一个来源一轮最多两次：整页补抽一次，补空或概括一次。
- 送入正文最多 24_000 字符。超长时保留开头 16_000 与结尾 8_000，并在运行记录写明已截断。不自动再请求一次把中段补上。
- 概括按最多 15 行一批。`excerpt` 与上一轮相同且 `brief` 非空的行不进入批次。

### 5.2 核对

每条模型候选：

- `excerpt` 必须是**本次原文**的子串。
- 货币金额、整数、小数和百分比必须以完整数字出现在该 `excerpt` 中，不能用较大数字的子串匹配。产品、模型与机构名也须在片段中，价目单位须有对应依据。
- 日期必须能被现有 `isoDate` 从片段或日期字段解析，且与字段一致。
- 价目价格还要过 `parseMoney`，展示价必须出现在片段中。
- 热榜链接为 `http` 开头，主机与该来源页面相同。
- 排名写成「榜上名次」时，片段里必须有这个名次；否则改为 `sorted`。不得填一个原文没有的榜单日期。
- 补空字段时，产品名和要填的额度或重置必须在同一条片段里。

未通过的候选不进入 `clean()`。导航词、缺字段、重复仍由现有清洗处理。

### 5.3 四栏

**价目**

规则结果里的价格、单位、币种、产品名不交给模型改。整页合格行为 0 时，才允许整页补抽为 `PriceDraft`。

规则已有行时，只填仍为空的 `quota`、`reset`、`condition`。已有价格保持原值。智谱 Coding Plan 的原文若没有价格，继续显示「未标价」，模型不能补一个价格。`brief` 按产品拼或概括成一句，包含产品、价格、条件和额度；不为每个格子单独请求。

**排名**

规则成功时不调用模型。`brief` 由程序拼成「榜单 · 名次或按分数排序 · 模型 · 分数 · 日期或页面未印日期」。整页为 0 时才补抽，提示要求有名次才填名次。

**热榜**

链接和名次以规则为准。与模型无关的仓库继续丢掉，不用模型捡回。整页为 0 时才补抽，每条必须有自己的链接。规则成功时，`brief` 用一句中文说明这个条目是什么、能做什么：GitHub 用趋势页上的仓库介绍，Hugging Face 优先用模型卡开头那段，没有时才用任务名和能力标签，Kaggle 用竞赛介绍。不写名次、热度、语言和下载量。介绍已经是中文，或同一片段已经有这句时，不再请求模型。

**厂商动态**

整页为 0 时按一次发布、一条新闻或一个组件状态补抽，类型只允许 `release`、`news`、`status`、`incident`。`cn_access` 仍只由 `mentionsMainland` 在清洗时改写。

规则已有行时写 `brief`：一句中文，不超过 80 字，数字必须在该行片段里。状态为「正常」的组件不调用模型，`brief` 为「正常」。概括不修改 `detail`。首页是否异常仍看状态字段，不看概括。

### 5.4 robots、403 和空页面

| 情况 | 抽取 | 模型 | 页面 |
| --- | --- | --- | --- |
| robots 不允许，或 robots.txt 读不到 | 不请求正文 | 不调用 | 有旧行则显示旧行和原因；没有旧行则显示原因，并链到替代来源 |
| HTTP 401、403 | 不把响应体交给 `extract` | 不调用 | 同上。原因保持「网站拒绝访问，不绕过」 |
| HTTP 200，但正文短于 800 字符且含登录、Sign in、Access denied | 不抽取 | 不调用 | 视为没拿到正文，保留旧行 |
| 整页合格行为 0，正文是正常文档 | 规则已失败 | 允许补抽 | 补抽仍为 0 时保留旧行，写「对不上原文」 |
| 从未成功且没有替代来源 | 无 | 不调用 | 显示「这一页还没有可显示的行」和运行原因，不显示空白表头冒充数据 |

替代来源是固定说明，不临时换站搜索：

| 拿不到的页面 | 改看 |
| --- | --- |
| ChatGPT 定价页、help.openai.com | P02 `learn.chatgpt.com` 的套餐 Markdown |
| arena.ai | R01 LMArena 在 Hugging Face 上的数据集 |
| `status.claude.com/api/` | N07 状态页 HTML |
| 未配置凭据的 Kaggle | 热榜其余来源；不编造竞赛 |

这些替代来源本来就在抓。被拒绝的地址不新增进队列。

### 5.5 边界

| 情况 | 处理 |
| --- | --- |
| 模型超时、非 JSON、HTTP 失败 | 规则有行则照常入库；规则无行则「没抽出」并留旧行 |
| 原文截断导致后半段漏抽 | 运行记录写明截断，不第二次补中段 |
| 概括里的数字对不上片段 | 这句 `brief` 留空，说明列仍用 `detail` |
| 同一产品片段里有两个价格 | 整页补抽时整条丢掉；补空时不改已有价格 |

## 6. 错误

| 情况 | 状态 | 用户看到的话 |
| --- | --- | --- |
| robots 不允许 | `skipped` | robots 原因。有旧行时加「下面是上次成功的内容」 |
| 401、403 | `failed` | 现有拒绝访问文案，同样保留旧行 |
| 模型无结果且规则无行 | `没抽出` | 「模型没有返回可用结果」加上是否留有旧行 |
| 核对后仍无行 | `没抽出` | 「模型抽出的字段对不上原文」 |
| 无密钥且规则有行 | `ok` | 与现在相同，只是没有模型概括 |

密钥不得出现在 `error`、日志和原始响应里。不自动重试。

## 7. 安全

密钥只来自 `.env`。送给模型的内容只包括本次 200 响应的公开正文和已入库片段，不附带 Kaggle 或其他密钥。拒绝页和登录墙不发送。模型输出不能绕过 `gate` 和 `clean()`。

## 8. 性能

一轮仍由人点击触发。价目大表、三张榜、热榜在规则成功时零次或仅一次概括，不按格子调用。厂商动态约 12 个来源；未变化的片段跳过，变化的行按 15 条一批。单次超时 45 秒。原有的同主机 2 秒抓取间隔不用于 DeepSeek。

栏目页读库里的 `brief`，打开页面不再等待模型。

## 10. 实现顺序

| 顺序 | 内容 | 依赖 |
| --- | --- | --- |
| 1 | 拿掉「版本较低就删表」，改为缺列才 `ALTER` | 无 |
| 2 | `gate` 与夹具测试 | 无 |
| 3 | 403、robots、登录墙保留旧行，且不调用模型 | 1 |
| 4 | 栏目在有旧行时显示原因和上次时间；无旧行时显示替代来源 | 3 |
| 5 | `deepseek.ts` 与整页补抽 | 2 |
| 6 | 价目只补空的额度、重置、条件；事件概括按 excerpt 缓存 | 5 |

每一步在不配密钥时都与当前抓取结果一致，除了第 3 步：被拒绝时不再把已有行留空。当前「没抽出」已经保留旧行；403 和 robots 若现在会把来源显示成没有行，第 3 步改正这一点。

## 11. 风险与假设

### 11.1 已改掉的问题

相对前一版草稿，这几处会损害三个目标，因此改掉了：

| 问题 | 改法 |
| --- | --- |
| 只有整页失败才概括，动态栏继续是英文 | 规则成功的动态也写一句中文 |
| 每轮都重新概括，句子来回变 | `excerpt` 不变则沿用原 `brief` |
| 模型补价可能覆盖规则价格 | 补空不改已有价格、名次、分数、链接 |
| 用 403 或 robots 页面去问模型，等于没有原文还要出数 | 拒绝页不进抽取，也不进模型 |
| 留空被理解成可以编一条替代数据 | 留空只允许显示上次成功行，或指向已经在抓的替代来源 |

### 11.2 风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 长页被截断 | 整页补抽漏掉后半 | 记录截断；已成功的表不整页重抽 |
| 旧行过期仍显示 | 用户以为是今天的价 | 必须写上次成功时间，且不计入今日变化 |
| 额度句子配错产品 | 错额度 | 产品名和数字必须在同一片段 |
| 迁移删库 | 已采集数据丢失 | 第 1 步先改迁移 |

### 11.3 假设

- `https://api.deepseek.com/chat/completions` 接受现在的请求体，模型名为 `deepseek-chat`。
- 24_000 字符和每源最多两次调用，只用于失败页和变化了的动态，整轮时间仍可接受。
- 排名用程序拼接的一行已经够看。热榜的一句中文只复述官方介绍。
- 不新增来源，不用搜索引擎缓存或其它网站填 403 和 robots 拒绝的空缺。
