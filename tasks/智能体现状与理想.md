# headline-chaser 智能体：现状与理想

对照日期：2026-10-31。现状以当前服务代码为准，不是产品文案。

## 审查发现

按严重程度排列。这些是现在就会走偏的地方，不是功能愿望。

1. **整理笔记不经确认就执行。** 对话模型一旦给出 `organize`，服务会立刻按它给的链接或素材路径抓页面、写笔记。调研、追踪、改方案都会先停在待确认；这一条不会。模型选错意图，或用户一句话被理解成整理，就会对外发请求并落盘。
2. **一次对话没有预算。** 系统提示、最近 40 条对话、整张主题卡、最新简报全文、最多 80 条事件、全部可搜索命令，打进同一次补全。没有步数、token 或费用上限。命令变多或简报变长时，这一跳会变慢、变贵，也更容易被截断。
3. **密钥会进本机终端记录。** 模型密钥只从环境变量读取，不进仓库。启动命令如果把密钥写在命令行上，终端记录里就有一份。对话和简报路径本身没有把密钥打进回答。
4. **进行中的采集只活在内存里。** 进程一停，任务状态消失。晨报用「这一天是否已经写出快照」避免重复；快照还没写成就崩溃时，下一轮会再跑一遍。
5. **认不出的意图被当成讨论。** 模型返回的 `intent` 不在约定集合里时，服务静默改成 `discuss`，不会告诉用户这不是它以为的动作。
6. **待确认只有一个槽。** 新的方案或采集会盖掉还没点的那一条，旧动作不再出现。

## 1. 运行时与控制流

| | 现状 | 理想 |
| --- | --- | --- |
| 循环 | 没有多步智能体循环。对话是一次补全，服务按意图做一件事。采集是固定流水线：搜索 → 归并 → 打开页面 → 写简报。 | 感知 → 推理 → 行动 → 观察可重复。每步把观察写回，直到简报合格或预算用尽。 |
| 规划 | 对话是单次分类（讨论、方案、调研、追踪、整理）。采集步骤写死，不先出计划。 | 方案阶段先规划再执行。采集阶段允许边做边改：某个源失败就换备用源，而不是整条流水线只有一条路。 |
| 预算 | 模型请求失败会再试一次，间隔 1 秒。搜索命令 90 秒超时，页面摘录 12 秒。没有最大步数、总超时、费用上限。 | 每次用户动作有步数和墙钟上限。超限停下来，说明停在哪一步。 |
| 人在回路 | 确认方案、开始调研、开始追踪必须点确认。调控里直接点按钮可以绕过对话。删除主题在界面上二次确认。整理笔记、晨报到点自动跑，不等确认。 | 发外网搜索、写档案、删主题必须确认。晨报是用户事先打开的授权，保留自动跑。整理笔记和删除一样，先给出将要写入的内容。 |

## 2. 模型与推理

| | 现状 | 理想 |
| --- | --- | --- |
| 分工 | 一个模型做全部事：对话意图、事件分组、简报、笔记正文。环境变量指定模型和地址。 | 对话和简报用主模型。分组、字段抽取可以用更小的模型。视觉只在需要看页面版式时才上。 |
| 提示 | 每条路径各有一段系统提示：对话确认主题卡、分组、写简报、抽正文。温度是 0。 | 一份角色说明加几份任务附录。角色写清边界：不编造数字和链接，搜索命令不能由模型直接调用。 |
| 结构 | 要求 JSON 对象。服务用括号截取解析，再按字段白名单过滤平台和引用。没有 JSON Schema 校验。 | 每种意图一份 schema。缺字段或类型不对就重试一次，仍失败就告诉用户，而不是当成讨论。 |
| 思考 | 不要求模型展示推理，用户也看不到。 | 内部可以有简短依据，默认不展示。用户展开时只看到「为什么选这些源」，不看到原始思维链。 |

## 3. Tool / Function calling

| | 现状 | 理想 |
| --- | --- | --- |
| 定义 | 模型没有工具列表。它只返回意图 JSON。真正的搜索是服务去跑 OpenCLI，参数只有关键词和 `-f json`。 | 搜索、打开页面、写笔记、改主题卡都是带 schema 的工具。模型填参数，服务校验。 |
| 路由 | 规则路由。模型选意图，代码决定能不能执行。可搜索命令来自目录，写操作动词被排除。 | 意图仍由规则把关。具体搜哪个平台可以让模型在允许集合里选，选到集合外就丢掉。 |
| 并行 | 采集时最多两个平台同时跑，同一平台的关键词串行。对话不并行调用。 | 互不依赖的搜索并行。写文件、改主题卡串行。 |
| 回灌 | 搜索结果不回到对话。它们进快照，下一轮对话只能看到简报正文和最多 80 条标题。 | 每步观察写成短记录：命令、条数、失败原因。下一轮只带摘要，不带原始 JSON。 |
| 失败 | 单条搜索失败记在快照里，其余继续。模型失败则整段对话报错，或简报退回检索摘要。不换工具。 | 主搜索失败换一个备用网页源。模型 JSON 不合格重试一次。仍失败就停，并指出哪一个源。 |

## 4. MCP

| | 现状 | 理想 |
| --- | --- | --- |
| 服务器 | 产品本身不接 MCP。外部能力是本机 OpenCLI 进程。 | 搜索仍走 OpenCLI。日历、邮件、仓库只在用户点名后挂上，不默认全开。 |
| 密钥 | 模型密钥在进程环境变量。OpenCLI 登录态由它自己的浏览器配置文件保管，需要登录的命令直接不纳入。 | 密钥留在环境或系统凭据里，不进仓库、不进对话、不进终端命令行。登录态站点继续默认关闭。 |
| 权限 | 目录一次查出全部可搜索命令，对话提示里会带上全部可选命令。 | 按这次主题挂一小份相关命令。其余要用户在调控里勾选才出现。 |
| 传输 | OpenCLI 用本机子进程，标准输入输出，不用 shell。 | 保持本地子进程。远程 MCP 只用于用户明确接入的服务。 |

## 5. Memory

| | 现状 | 理想 |
| --- | --- | --- |
| 短期 | 当前这一次请求里的系统提示、最近 40 条对话正文、主题卡、最新简报、事件标题。引用不写回下一轮提示。 | 工作记忆只保留本轮问题和未完成的待确认动作。更早的对话压成几句摘要。 |
| 长期 | 主题卡写在主题文件夹：关键词、排除词、受众、已报过的热点阶段。没有向量库，没有跨主题档案。 | 主题卡继续当长期事实。跨主题偏好（受众、常用源）单独一份，用户可改。 |
| 隔离 | 每个主题一份对话记录和一份待确认文件。换主题看不到另一边。 | 保持按主题隔离。桌面只索引标题，不把别的主题正文注入当前对话。 |
| 写入 | 对话每条都自动追加。热点阶段在追踪成功后写入主题卡。没有「记住 / 忘掉」。 | 自动只记主题卡和已确认的结论。用户说忘掉时删对应条目。相同标题不重复记。 |
| 检索 | 没有检索。相关材料是「最新一份」直接塞进提示。 | 先按关键词在本主题档案里找，不够再把摘录放进提示，并带来源路径。 |

## 6. 知识与检索（RAG）

| | 现状 | 理想 |
| --- | --- | --- |
| 语料 | 本主题的快照、简报、笔记、素材。搜索结果来自 OpenCLI，不是事先建好的库。 | 仍以本主题文件夹为唯一语料。网页只在这次采集里临时打开。 |
| 索引 | 没有切块、向量或索引。分组最多看 120 条标题。 | 档案变多后再做关键词索引。先不要上向量库。 |
| 改写 | 查询由主题卡拼出来：中文词、英文词、必须照看的对象。不做查询改写，也不重排。 | 调研前用主题卡生成两三条查询。结果按日期和是否含必须照看的词排序。 |
| 溯源 | 简报每条有来源名和原文链接。对话引用必须能在文件夹或已采集链接里找到，否则丢掉。 | 保持。模型写出的数字、价格、日期必须能在摘录里找到，否则不写。 |

## 7. 状态与编排

| | 现状 | 理想 |
| --- | --- | --- |
| 图 | 没有图。采集是一条函数流水线。对话是一次 switch。 | 采集画成少量节点：搜索、筛选、打开、写作、落盘。失败从对应节点重试，不从头再来。 |
| 子代理 | 没有。分组和写简报是同一次任务里的另两次模型调用。 | 不拆成多个自主代理。分组和写作继续当流水线节点。 |
| 后台 | 采集请求立刻返回，界面轮询当前任务。晨报每 30 秒看一次谁到点。任务表在内存。 | 任务状态写进主题文件夹，重启后能接着看。同一主题同时只跑一个采集。 |
| 幂等 | 同一主题采集进行中会拒绝再开。晨报用名义日期判断今天是否已跑。待确认被覆盖时，旧动作不会执行。 | 写快照用同一标识重复提交不产生第二份。待确认被覆盖前先告诉用户旧的作废了。 |

## 8. 多模态与环境

| | 现状 | 理想 |
| --- | --- | --- |
| 浏览器 | 界面用本机页面。采集不操作浏览器；OpenCLI 自己的浏览器命令可以跑，但产品不点页面。 | 搜索继续交给 OpenCLI。产品不去点击登录、填表。 |
| 命令与文件 | 服务能跑 OpenCLI，能读写主题文件夹和应用数据目录。选文件夹用系统对话框。路径必须落在主题目录里。 | 保持。模型不能拼任意命令。删除主题目录仅限工作台自己建出来的文件夹。 |
| 语音与图像 | 没有语音、图像或视频入口。页面摘录是去掉标签的文本。 | 封面和简报保持文字。需要看图表时再加一次视觉调用，结果仍要带来源。 |

## 9. 安全与治理

| | 现状 | 理想 |
| --- | --- | --- |
| 权限 | 读搜索和写档案分开。写操作类 OpenCLI 命令不进目录。需要登录的命令默认不可勾选。 | 只读工具默认可建议。写档案、删主题、外发请求分成三档，后两档必须确认。 |
| 名单 | 平台必须出现在目录里且能收成标题加链接。引用必须是已采集链接或主题内文件。没有域名白名单。整理笔记会按模型给的 http(s) 地址去抓。 | 抓取只允许这次搜索结果里的链接，或用户贴进素材的链接。模型新编的地址不抓。 |
| 密钥 | 不写进源码。回答路径不回显密钥。启动命令行可能把密钥留在本机终端记录。 | 启动时只从环境变量读。日志和终端记录不出现密钥。 |
| 审计 | 采集步骤留在内存任务里，成功后快照记下每个平台成败。没有跨主题的审计日志。 | 每个主题一份追加日志：时间、动作、命令、结果条数。不含正文全文和密钥。 |

## 10. 评测与可观测

| | 现状 | 理想 |
| --- | --- | --- |
| 追踪 | 没有逐步记录提示、工具、耗时、token。失败多半只在界面上显示一句。 | 开发时可打开一条轨迹：这次用了哪些命令、模型是否退回摘要、花了多久。默认对用户只显示结果。 |
| 评测 | 有流程测试：确认方案、采集、追踪、引用不越界、删除主题不误伤别的主题。没有一组固定问题看简报是否编造。 | 留一套固定主题夹具。每次改提示或流水线，检查简报是否含原文链接、是否在模型失败时退回摘要。 |
| 反馈 | 没有点踩。模型写失败时简报退回检索摘要，用户看得到那句「这是检索摘要」。 | 用户标「这句不实」后，记下对应链接和句子，下次写简报时把这条排除。不自动改提示。 |

## 已经站住的部分

这些不要推倒重来。

- 对话不直接搜。搜索发生在用户确认之后，或用户在调控里按下按钮。
- 平台名和引用都有白名单。写操作命令和需要登录的命令默认不进可搜索列表。
- 简报的说明和「为何关注」来自页面摘录；模型失败就退回检索摘要，不另编一套套话。
- 记忆按主题分开：主题卡、对话、快照都在这个主题自己的目录里。
- 同一主题的采集不会叠着跑。晨报用名义日期避免同一天写两遍。
