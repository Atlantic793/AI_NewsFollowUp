# headline-chaser 智能体：现状与理想

对照日期：2026-11-01。现状以当前服务代码为准；原始需求见 PRD/SPEC，启动和复现命令见 [README](../README.md)。

## 已落实的改动

本节更新旧版审查发现，避免把已经实现的能力继续列成缺陷。

1. **对话整理先预览、再确认。** 只接受已采集链接或主题素材中的链接；确认后才抓取页面并写笔记。链接或素材整理接口仍受计划确认和来源限制；用户手写笔记可以直接保存。
2. **对话与任务有预算。** 对话上下文估算上限 6000 token，模型调用等待上限 45 秒；采集阶段检查 24 步和 4 分钟预算。常驻进程请求预算包含排队时间，过期请求不会执行。
3. **进程与凭据隔离。** 模型密钥仍从环境变量读取；启动参数检查会拒绝常见的密钥参数形式。采集进程采用环境变量白名单，不继承模型密钥、数据库凭据和 `NODE_OPTIONS`。
4. **任务状态落盘。** 重启时结合快照恢复状态；未完成任务标记为 `incomplete`，不自动重跑，对应晨报日期可保持暂停。
5. **未知意图有提示。** 无法识别的意图不会静默当作讨论；替换待确认动作时提示上一条将作废，待确认仍是单槽设计。
6. **目录发现复用运行时。** OpenCLI 2.0.2 是项目依赖；常驻采集进程批量读取命令注册表，目录缓存 24 小时，登录检测在独立短时进程中后台运行。

## 已验证范围

42 项自动化测试、类型检查、Lint、前端构建通过；真实公开 npm 源已走通主题创建、方案确认、搜索、快照和简报。133 条目录项与旧实现逐字段一致，92 条可选。目录首次读取约 644 毫秒、内存缓存读取约 1.4 毫秒，详见 [验收记录](../docs/performance/opencli-integration-20261101.json)。性能为本机测量；浏览器登录态采集和模型生成质量未在本轮实测。

## 1. 运行时与控制流

| | 现状 | 理想 |
| --- | --- | --- |
| 循环 | 没有多步智能体循环。对话是一次补全，服务按意图做一件事。采集是固定流水线：搜索 → 归并 → 打开页面 → 写简报。 | 感知 → 推理 → 行动 → 观察可重复。每步把观察写回，直到简报合格或预算用尽。 |
| 规划 | 对话是单次分类（讨论、方案、调研、追踪、整理）。采集步骤写死，不先出计划。 | 方案阶段先规划再执行。采集阶段允许边做边改：某个源失败就换备用源，而不是整条流水线只有一条路。 |
| 预算 | 对话上下文与模型等待、采集阶段步数与时间、单次搜索请求均有预算；搜索预算含排队。没有实际 token 账单或费用上限。 | 统一传播取消信号，记录实际 token 与费用，明确各阶段预算。 |
| 人在回路 | 对话中的方案、调研、追踪和笔记先待确认；调控按钮直接发起对应动作。删除主题有界面确认，已开启的晨报自动执行。 | 保留确认边界，进一步明确各种动作将读取和写入的内容。 |

## 2. 模型与推理

| | 现状 | 理想 |
| --- | --- | --- |
| 分工 | 一个模型做全部事：对话意图、事件分组、简报、笔记正文。环境变量指定模型和地址。 | 对话和简报用主模型。分组、字段抽取可以用更小的模型。视觉只在需要看页面版式时才上。 |
| 提示 | 每条路径各有一段系统提示：对话确认主题卡、分组、写简报、抽正文。温度是 0。 | 一份角色说明加几份任务附录。角色写清边界：不编造数字和链接，搜索命令不能由模型直接调用。 |
| 结构 | 要求 JSON 对象。服务用括号截取解析，再按字段白名单过滤平台和引用。没有 JSON Schema 校验。 | 每种意图一份 schema。缺字段或类型不对就重试一次，仍失败就告诉用户，而不是当成讨论。 |
| 思考 | 不要求模型展示推理，用户也看不到。 | 内部可以有简短依据，默认不展示。用户展开时只看到「为什么选这些源」，不看到原始思维链。 |

## 3. Tool / Function calling

| | 现状 | 理想 |
| --- | --- | --- |
| 定义 | 模型只返回意图 JSON。服务通过薄适配层向常驻进程发送搜索动作；关键词作为对象参数交给 OpenCLI 执行器。 | 搜索、打开页面、写笔记、改主题卡都是带 schema 的工具。模型填参数，服务校验。 |
| 路由 | 规则路由。模型选意图，代码决定能不能执行。可搜索命令来自目录，写操作动词被排除。 | 意图仍由规则把关。具体搜哪个平台可以让模型在允许集合里选，选到集合外就丢掉。 |
| 并行 | 调度层最多两个平台在途；常驻进程因上游全局会话状态而串行执行搜索，队列最多 64 项。登录检测使用独立进程，目录并发请求合并。 | 确认会话隔离后再按来源或 worker 做受控并行。 |
| 回灌 | 搜索结果进入快照，下一轮对话读取最新简报摘录和最多 20 条事件标题及链接。 | 每步观察写成短记录：命令、条数、失败原因。下一轮只带摘要，不带原始 JSON。 |
| 失败 | 单条搜索失败记在快照里，其余继续。模型失败则整段对话报错，或简报退回检索摘要。不换工具。 | 主搜索失败换一个备用网页源。模型 JSON 不合格重试一次。仍失败就停，并指出哪一个源。 |

## 4. MCP

| | 现状 | 理想 |
| --- | --- | --- |
| 服务器 | 产品本身不接 MCP。OpenCLI 作为项目依赖运行在常驻采集进程中。 | 搜索仍走 OpenCLI。日历、邮件、仓库只在用户点名后挂上，不默认全开。 |
| 密钥 | 模型密钥在进程环境变量。OpenCLI 登录态由它自己的浏览器配置文件保管，需要登录的命令直接不纳入。 | 密钥留在环境或系统凭据里，不进仓库、不进对话、不进终端命令行。登录态站点继续默认关闭。 |
| 权限 | 目录批量发现只读搜索命令。对话优先带当前主题已选且可用的命令，最多 12 条；尚未选源时取最多 12 条可用命令。 | 按主题相关度推荐信息源，并给出选择依据。 |
| 传输 | 常驻采集使用 Node IPC；既有浏览器配方保留项目内 CLI 兼容路径。搜索不拼接 shell 命令。 | 保持本地进程边界。远程 MCP 只用于用户明确接入的服务。 |

## 5. Memory

| | 现状 | 理想 |
| --- | --- | --- |
| 短期 | 最近 12 条对话、每条最多 500 字符；最新简报最多 1800 字符，最多 20 条事件，最多 12 个命令。整体超预算继续裁剪历史。 | 工作记忆保留本轮问题与待确认动作，更早的对话压成摘要。 |
| 长期 | 主题卡写在主题文件夹：关键词、排除词、受众、已报过的热点阶段。没有向量库，没有跨主题档案。 | 主题卡继续当长期事实。跨主题偏好（受众、常用源）单独一份，用户可改。 |
| 隔离 | 每个主题一份对话记录和一份待确认文件。换主题看不到另一边。 | 保持按主题隔离。桌面只索引标题，不把别的主题正文注入当前对话。 |
| 写入 | 对话每条都自动追加。热点阶段在追踪成功后写入主题卡。没有「记住 / 忘掉」。 | 自动只记主题卡和已确认的结论。用户说忘掉时删对应条目。相同标题不重复记。 |
| 检索 | 没有检索。相关材料是「最新一份」直接塞进提示。 | 先按关键词在本主题档案里找，不够再把摘录放进提示，并带来源路径。 |

## 6. 知识与检索（RAG）

| | 现状 | 理想 |
| --- | --- | --- |
| 语料 | 本主题的快照、简报、笔记、素材。搜索结果来自 OpenCLI，不是事先建好的库。 | 仍以本主题文件夹为唯一语料。网页只在这次采集里临时打开。 |
| 索引 | 没有切块、向量或索引。分组最多看 120 条标题。 | 档案变多后再做关键词索引。先不要上向量库。 |
| 改写 | 查询由主题卡拼出来：中文词、英文词、必须照看的对象。不做查询改写，也不重排。 | 调研前用主题卡生成两三条查询。结果按日期和是否含必须照看的词排序。 |
| 溯源 | 简报每条有来源名和原文链接。对话引用必须能在文件夹或已采集链接里找到，否则丢掉。 | 保持。模型写出的数字、价格、日期必须能在摘录里找到，否则不写。 |

## 7. 状态与编排

| | 现状 | 理想 |
| --- | --- | --- |
| 图 | 没有图。采集是一条函数流水线。对话是一次 switch。 | 采集画成少量节点：搜索、筛选、打开、写作、落盘。失败从对应节点重试，不从头再来。 |
| 子代理 | 没有。分组和写简报是同一次任务里的另两次模型调用。 | 不拆成多个自主代理。分组和写作继续当流水线节点。 |
| 后台 | 采集请求立刻返回，界面轮询任务；晨报每 30 秒检查。任务状态写在应用数据目录的主题记录下，档案快照仍写在主题文件夹。 | 支持明确的阶段重试和取消，继续限制同一主题只运行一个采集。 |
| 幂等 | 同主题拒绝叠加采集；晨报按名义日期去重。恢复时未完成任务不自动重跑；替换待确认动作时提示旧动作作废。 | 对重试和取消建立明确的作业标识规则。 |

## 8. 多模态与环境

| | 现状 | 理想 |
| --- | --- | --- |
| 浏览器 | 浏览器型适配器需已连接 OpenCLI 扩展；搜索前检查连接状态。保留无适配器浏览器配方入口，默认配方清单为空；不自动登录。 | 搜索继续交给 OpenCLI，按实际来源验证浏览器会话和页面能力。 |
| 命令与文件 | 服务能跑 OpenCLI，能读写主题文件夹和应用数据目录。选文件夹用系统对话框。路径必须落在主题目录里。 | 保持。模型不能拼任意命令。删除主题目录仅限工作台自己建出来的文件夹。 |
| 语音与图像 | 没有语音、图像或视频入口。页面摘录是去掉标签的文本。 | 封面和简报保持文字。需要看图表时再加一次视觉调用，结果仍要带来源。 |

## 9. 安全与治理

| | 现状 | 理想 |
| --- | --- | --- |
| 权限 | 读搜索和写档案分开。写操作类 OpenCLI 命令不进目录。需要登录的命令默认不可勾选。 | 只读工具默认可建议。写档案、删主题、外发请求分成三档，后两档必须确认。 |
| 名单 | 平台需满足只读权限、检索参数和结果列要求，执行前再次检查。笔记链接需来自已采集结果或主题素材；引用需是已采集链接或主题内文件。 | 持续验证适配器元数据和来源边界；本地扩展代码仍需可信。 |
| 密钥 | 模型从环境读取，启动检查拒绝常见密钥参数形式；采集环境使用白名单。不会清理已经存在的终端历史。 | 继续减少凭据传播，并按具体新增信息源审查其必需变量。 |
| 审计 | 每个主题在应用数据目录记录 trace.jsonl，包含动作、阶段、耗时或条数；任务状态和平台成败另行落盘。 | 完善按任务串联的轨迹，继续避免记录正文和凭据。 |

## 10. 评测与可观测

| | 现状 | 理想 |
| --- | --- | --- |
| 追踪 | 已记录对话、采集和任务轨迹；token 数是字符估算，不是模型账单。尚未完整记录模型实际用量和逐节点观察。 | 完整关联命令、阶段、降级路径、实际用量与耗时。 |
| 评测 | 42 项测试覆盖既有流程以及目录缓存、进程生命周期、队列期限和环境隔离；有独立公开源验收脚本，尚无模型事实准确性评测集。 | 建立固定主题和来源摘录，评估简报事实与引用是否一致。 |
| 反馈 | 没有点踩。模型写失败时简报退回检索摘要，用户看得到那句「这是检索摘要」。 | 用户标「这句不实」后，记下对应链接和句子，下次写简报时把这条排除。不自动改提示。 |

## 已经站住的部分

这些不要推倒重来。

- 对话不直接搜。搜索发生在用户确认之后，或用户在调控里按下按钮。
- 平台名和引用都有白名单。写操作命令和需要登录的命令默认不进可搜索列表。
- 简报的说明和「为何关注」来自页面摘录；模型失败就退回检索摘要，不另编一套套话。
- 记忆按主题分开：主题卡、对话、快照都在这个主题自己的目录里。
- 同一主题的采集不会叠着跑。晨报用名义日期避免同一天写两遍。
