# PRD: 主题跟进第一版

## Introduction

这是一个给个人用的主题跟进工具，也是一份开放选题的智能体参赛作品。用户从主页新建主题，每个主题是一个工作台，并挂钩一个本地文件夹。工作台里完成收集、追踪、整理和讨论。档案以这个文件夹为准，不另做一套只存在网页里的知识库。

工作台分成三区：

- **文件区**：展示挂钩文件夹里的内容。
- **工作面板**：看总状况、调控采集、阅读概括。每天和前一天的对比放在这里。
- **智能体区**：围绕该主题对话。讨论直接回答；整理会写入笔记；收集和改平台先落到调控面板，用户确认后才执行。

产品的主优势是每天和前一天比：晨报对照前一个自然日的最后一份快照，只写变化，并且每条结论都能点回原链接。同一天里的手动追踪则对照紧挨着的上一份快照。简报写明对照的是哪一天、哪一份快照。

智能体不替用户决定本次是否收集、是否改计划。它负责：把一句话拆成关键词和预选平台、把多平台重复内容收成同一件事、按条数规则写出变化结论、基于该文件夹回答问题、在用户点名时把链接或素材整理成笔记。四种结论不交给模型改写。

信息源由用户勾选。清单来自运行时 OpenCLI 能按关键词搜索、并且能收成统一条目的平台，不写死 GitHub、B 站或小红书。发帖、点赞等写操作不进入清单。不能收成统一条目的命令不能被勾选。浏览器自动化只用来打开已经勾选、但没有直接接口的平台，不接受用户随意填写网址。

挂钩文件夹的结构：

- `主题.md`：原话、关键词、勾选的平台、晨报时间、文件夹路径。
- `简报/`：每天的短简报。
- `快照/`：每次采集的原始结果，含勾选平台和各平台成败。
- `笔记/`：整理出来的正文。
- `素材/`：用户放入的文件和 URL。

一份档案里的材料对应这些文件：

- **主题**：`主题.md`。
- **快照**：`快照/` 中的一次采集。条目包含标题、链接、平台、时间和摘要。
- **事件**：同一次快照里、被收成「同一件事」的一簇条目，并保留各平台来源。
- **简报**：`简报/` 中的一份短文。没有可对照的快照时，只有事件列表。
- **笔记**：`笔记/` 中的一篇正文。

变化结论只有四种，表示的是两次采集里、两份快照都勾选的平台上的差别，不是全网真实热度：

- **新出现**：对照快照没有这件事。
- **升温**：对照快照有，这次在两边都勾选的平台上来源条数变多，或多了一个两边都勾选、但上次没有出现的平台。
- **还在**：对照快照有，这次还有，条数没有变多，也没有上述新平台。条数变少但仍采到，也算还在。
- **正在消退**：对照快照有，这次在两边都勾选的平台上没采到。

另有一个单独标签，不算四种结论之一：

- **新加入的源**：这次新勾上的平台采到的内容。它不把已有事件算成升温。今天取消勾选的平台，也不把昨天的条目算成正在消退。

## Goals

- 用户从主页进入主题工作台，而不是从四个独立功能入口开始。
- 每个主题挂钩一个本地文件夹，文件区与该文件夹内容一致。
- 用户可以用一句话建立主题，并在采集前确认关键词、平台和文件夹。
- 用户可以从 OpenCLI 当前能搜索、且能收成统一条目的平台里勾选。
- 每日晨报对照前一个自然日的最后一份快照；同一天的手动追踪对照上一份快照。
- 每条结论都能点回至少一条原链接，简报同时出现在工作面板和 `简报/`。
- 平台勾选变化和单平台采集失败，都不会被写成热度变化。
- 用户可以在对话或文件区点名，把能解析的链接或素材整理进 `笔记/`。
- 对话可以解释结论和计划，但不能在用户确认前启动收集或改写平台。
- 演示可以走完：新建、挂钩文件夹、改勾选、收集、再追踪、在总状况打开原链接，并在对话里问到一份文件夹中的材料。

## User Stories

### US-001: 打开应用看到主题列表

**Description:** As a user, I want the home page to show my topics and the latest change counts so that I can decide which workspace to open.

**Acceptance Criteria:**

- [ ] 打开应用进入主题列表，而不是收集、追踪、整理、讨论的入口页
- [ ] 没有任何主题时，页面只有新建入口，并说明还没有主题
- [ ] 已有主题时，每张卡片显示原话、上次采集时间、晨报开或关
- [ ] 最近一份含四种结论的简报存在时，卡片显示新出现、升温、正在消退的条数，并标明对照日期
- [ ] 还没有这种简报时，卡片不显示这三项条数
- [ ] 从未采集过的主题，上次采集时间显示为「尚未采集」
- [ ] 点击卡片进入该主题工作台，工作面板默认打开「总状况」
- [ ] 关闭应用再打开，已创建的主题仍在
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-002: 新建主题并挂钩文件夹

**Description:** As a user, I want a new topic to bind one local folder and stop at plan confirmation so that nothing is collected before I agree.

**Acceptance Criteria:**

- [ ] 新建时用户输入一句话
- [ ] 系统默认创建一个空的本地文件夹并挂钩；用户可以在确认前改挂到已有文件夹
- [ ] 一个主题同时只挂钩一个文件夹
- [ ] 进入工作台后，调控面板处于待确认：可见关键词、预勾选平台和文件夹路径
- [ ] 可勾选平台来自运行时查出的 OpenCLI 搜索命令，且该平台能把结果收成标题、链接、平台、时间、摘要
- [ ] 清单不写死为 GitHub、B 站、小红书；这三个平台若满足上一条，可以出现，也可以不出现
- [ ] 写操作命令不出现在清单中
- [ ] 不能收成统一条目的命令显示为不可选，并说明暂不能纳入对比
- [ ] 需要登录且当前未登录的平台显示「需要登录」，不默认勾选
- [ ] 用户可以增删关键词、勾选或取消任何可选平台
- [ ] 关键词为空或平台一个都没选时，确认按钮不可用
- [ ] 确认之前不产生快照；对话可以解释预选平台，但不能启动收集
- [ ] 确认后，原话、关键词、平台和路径写入 `主题.md`，并显示在调控面板
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-003: 在调控面板修改采集计划

**Description:** As a user, I want to change keywords, platforms, and the morning-report time in the control tab so that the next run uses the new plan.

**Acceptance Criteria:**

- [ ] 已确认主题的调控面板可以修改关键词、平台和晨报时间
- [ ] 平台清单规则与 US-002 相同
- [ ] 保存后，下一次收集、追踪、晨报使用新计划，并更新 `主题.md`
- [ ] 保存不会删除已有快照、简报和笔记
- [ ] 收集、追踪、晨报开始前不再要求重新确认整份计划
- [ ] 调控面板展示当前挂钩路径，并提供在系统文件管理器中打开该文件夹
- [ ] 用户改挂到另一个文件夹后，文件区改为显示新文件夹，不自动搬走旧文件夹里的文件
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-004: 从调控面板收集并留下快照

**Description:** As a user, I want to collect on demand from the control tab so that a snapshot file appears in the topic folder.

**Acceptance Criteria:**

- [ ] 计划确认后，调控面板提供「现在收集」
- [ ] 没有快照时，调控面板里的「现在追踪」和晨报时间不可用，并说明要先收集一次
- [ ] 点击「现在收集」后，系统只采集已确认的关键词和已勾选平台
- [ ] 已有直接接口的平台走对应 OpenCLI 命令；已勾选但没有直接接口的平台才用浏览器打开
- [ ] 采集结束在 `快照/` 写入一份快照，记录采集时间、这次勾选的平台、每个平台成功或失败
- [ ] 每个成功采到的条目都有标题、链接、平台、时间和摘要
- [ ] 链接完全相同的条目合并为一条
- [ ] 同一快照内，同一件事的多条来源显示为一个事件，事件下列出来源
- [ ] 这是该主题的第一份快照时，总状况只展示「这次看到的事件」，不显示四种结论
- [ ] 某个平台采集失败时，快照仍保存其他平台的结果，并写明失败平台
- [ ] 全部平台都失败时，不把上一份快照里的事件写成正在消退
- [ ] 用户不能通过填写任意网址新增一个信息源
- [ ] 关闭应用再打开，`快照/` 中的该文件仍在，文件区能看见
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-005: 同一天内对照上一份快照做热点追踪

**Description:** As a user, I want a manual refresh to compare with the immediately previous snapshot so that I can see what changed since the last run.

**Acceptance Criteria:**

- [ ] 已有快照时，调控面板的「现在追踪」会再采一次，并在 `快照/` 新增一份快照
- [ ] 对照的是时间上紧挨着的上一份快照，总状况和简报写明那份快照的日期和时间
- [ ] 只在两份快照都勾选的平台上计算四种结论
- [ ] 上次没有、这次有的事件标为新出现
- [ ] 上次有、这次在两边都勾选的平台上来源条数更多的事件标为升温
- [ ] 上次有、这次多了一个两边都勾选过、但上次没有出现的平台的事件标为升温
- [ ] 上次有、这次还有、条数没有变多且没有上述新平台的事件标为还在，包括条数变少的情况
- [ ] 上次有、这次在两边都勾选的平台上没采到的事件标为正在消退
- [ ] 这次新勾选的平台，其条目进入「新加入的源」，不把已有事件标为升温
- [ ] 这次取消勾选的平台，不把该平台上的旧条目标为正在消退
- [ ] 某个两边都勾选的平台这次采集失败时，不因为该平台缺结果而把事件标为正在消退
- [ ] 升温结论写明条数或新增平台，例如「上次 1 条，这次 3 条」
- [ ] 用固定夹具覆盖以上输入输出，结论与夹具一致
- [ ] 类型检查与 lint 通过

### US-006: 在工作面板阅读带链接的短简报

**Description:** As a user, I want the status and summary tabs to show the brief so that I can open the original source for every claim.

**Acceptance Criteria:**

- [ ] 每次收集、追踪、晨报都在 `简报/` 写入一份短简报
- [ ] 「概括」页签显示最新一份简报
- [ ] 「总状况」在有四种结论时按新出现、升温、还在、正在消退分组，并单独列出新加入的源
- [ ] 简报写明对照的是哪一天、哪一份快照；没有对照时写明没有可对照的快照
- [ ] 简报中的每条结论或事件至少有一条可打开的原链接
- [ ] 新出现、升温、还在、新加入的源使用本次快照中的链接
- [ ] 正在消退使用对照快照中的链接
- [ ] 没有可用链接的结论不出现在简报里
- [ ] 文件区可以点开某次快照，看到该次事件、勾选平台和对应简报
- [ ] 简报不生成五章节长文，不提供 PDF，不向主题页以外的地址推送
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-007: 每日晨报对照前一天

**Description:** As a user, I want each morning brief to compare with yesterday so that the status tab and the folder both show what changed.

**Acceptance Criteria:**

- [ ] 没有快照时，晨报时间设置不可用，并说明要先做一次收集
- [ ] 已有快照时，用户可以在调控面板设定每天的一个时间，或关闭晨报
- [ ] 主题卡片上能看出晨报是开还是关
- [ ] 应用正在运行且到达设定时间时，自动按当前计划再采一次
- [ ] 自动运行不弹出计划确认
- [ ] 晨报对照前一个自然日的最后一份快照，并在简报上写明那个日期
- [ ] 昨天没有快照时，不改用更早的快照；总状况只列出这次看到的事件，并写明昨天没有可对照的快照
- [ ] 昨天有快照时，四种结论和新加入的源的规则与 US-005 相同，只是对照对象换成昨天最后一份快照
- [ ] 自动运行后，总状况和 `简报/`、`快照/` 同时更新，采集时间是实际运行时间
- [ ] [Assumption] 设定时间到达时应用没有运行，则下次启动补跑一次，并标明实际采集时间；对照日期仍是该次晨报所属日期的前一个自然日
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-008: 把链接或素材整理成笔记

**Description:** As a user, I want to turn a link or a file in the topic folder into a note so that the text stays in the same archive.

**Acceptance Criteria:**

- [ ] 计划确认后就可以整理，不要求主题已有快照
- [ ] 用户可以在文件区提交一条链接，或在对话里点名一条链接或一份素材
- [ ] 能解析出正文时，在 `笔记/` 生成一篇笔记，包含来源和正文，文件区立即可见
- [ ] 可解析范围不写死为 B 站和小红书；已有解析能力的平台必须可用，后来补上解析能力的平台也可用
- [ ] 笔记不参与来源条数统计，不单独改变四种结论，也不算作新加入的源
- [ ] 空链接，或还不能解析出正文的材料，说明原因，且不新增笔记
- [ ] 关闭应用再打开，笔记文件仍在
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-009: 文件区与本地文件夹一致

**Description:** As a user, I want the file pane to be the bound folder so that I can add materials from the operating system and see them in the topic.

**Acceptance Criteria:**

- [ ] 文件区列出 `主题.md`、`简报/`、`快照/`、`笔记/`、`素材/`
- [ ] 用户把文件放进该文件夹的 `素材/` 后，文件区能看见，且不自动变成笔记
- [ ] 用户在 `素材/` 保存一条 URL 后，文件区能看见该 URL
- [ ] 对话回答本主题问题时，引用限于该文件夹中的文件，或快照里的原链接
- [ ] 对话不把文件夹以外的材料写成这个主题的证据
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

### US-010: 在对话里讨论，收集仍要确认

**Description:** As a user, I want to ask about this topic in chat so that I can understand the brief without the agent collecting on its own.

**Acceptance Criteria:**

- [ ] 工作台右侧有该主题的对话，打开主题后可以接着上次的对话
- [ ] 用户询问某条结论时，回答指向总状况中的条目，或 `简报/`、`快照/`、`笔记/`、`素材/` 中的文件
- [ ] 用户在对话里要求现在收集或修改平台时，调控面板列出将要执行的动作，在用户于调控面板确认之前不采集、不保存新计划
- [ ] 用户在对话里点名整理时，按 US-008 写入笔记，不改变四种结论
- [ ] 计划未确认时，对话不提供能够启动收集的确认动作
- [ ] 类型检查与 lint 通过
- [ ] 在浏览器中验证（例如通过 run skill）

## Functional Requirements

- FR-1: 系统必须把主题列表作为应用首页。
- FR-2: 系统必须在主题卡片上显示原话、上次采集时间和晨报开关。
- FR-3: 系统必须在存在含四种结论的简报时，在卡片上显示新出现、升温、正在消退的条数和对照日期。
- FR-4: 系统必须允许用户用一句话创建主题。
- FR-5: 系统必须在创建主题时挂钩恰好一个本地文件夹。
- FR-6: 系统必须默认新建空文件夹，并允许用户在确认前改挂已有文件夹。
- FR-7: 系统必须在挂钩文件夹中使用 `主题.md`、`简报/`、`快照/`、`笔记/`、`素材/`。
- FR-8: 系统必须在新建后进入工作台，并使调控面板停在待确认计划。
- FR-9: 系统必须在计划确认前拒绝收集，包括从对话发起的收集。
- FR-10: 系统必须在第一次收集前，把那句话拆成关键词和预选平台并交给用户确认。
- FR-11: 系统必须在运行时从 OpenCLI 查出可按关键词搜索的命令，作为信息源候选。
- FR-12: 系统必须只允许勾选能把结果收成标题、链接、平台、时间和摘要的平台。
- FR-13: 系统必须把不能收成统一条目的命令显示为不可选。
- FR-14: 系统必须不把写操作命令放进信息源清单。
- FR-15: 系统必须对需要登录且未登录的平台显示「需要登录」，并且不默认勾选。
- FR-16: 系统必须在关键词为空或未选择任何平台时拒绝确认。
- FR-17: 系统必须把确认后的关键词、平台和文件夹路径写入 `主题.md`。
- FR-18: 系统必须允许用户在调控面板修改关键词、平台和晨报时间，并只让修改影响之后的采集。
- FR-19: 系统必须在收集、追踪和晨报开始前直接使用当前已确认计划，不再询问整份计划。
- FR-20: 系统必须把主题工作台分成文件区、工作面板和智能体区。
- FR-21: 系统必须让工作面板包含「总状况」「调控」「概括」三个页签，进入主题时默认打开「总状况」。
- FR-22: 系统必须让文件区展示挂钩文件夹的五类内容。
- FR-23: 系统必须在用户向 `素材/` 放入文件后，在文件区显示该文件，且不自动生成笔记。
- FR-24: 系统必须允许用户改挂文件夹，并在改挂后只显示新文件夹，不自动迁移旧文件。
- FR-25: 系统必须提供在系统文件管理器中打开当前挂钩文件夹的入口。
- FR-26: 系统必须只采集该次已勾选的平台。
- FR-27: 系统必须对已有直接接口的已勾选平台使用对应 OpenCLI 命令。
- FR-28: 系统必须只对已勾选且没有直接接口的平台使用浏览器自动化。
- FR-29: 系统必须拒绝把任意网址添加为信息源。
- FR-30: 系统必须在收集、追踪和晨报后把快照写入 `快照/`，并包含采集时间、勾选平台和各平台成败。
- FR-31: 系统必须为每个成功条目保存标题、链接、平台、时间和摘要。
- FR-32: 系统必须把同一快照中链接完全相同的条目合并为一条。
- FR-33: 系统必须把同一快照中的同一件事聚类为一个事件，并保留多个来源。
- FR-34: 系统必须在没有可对照快照时只展示事件，不展示四种结论。
- FR-35: 系统必须在不存在快照时禁用「现在追踪」和晨报设置。
- FR-36: 系统必须让手动热点追踪对照时间上紧挨着的上一份快照。
- FR-37: 系统必须让每日晨报对照前一个自然日的最后一份快照。
- FR-38: 系统必须在昨天没有快照时避免使用更早的快照作为晨报对照，并写明昨天没有可对照的快照。
- FR-39: 系统必须在简报上写明对照的日期和快照时间。
- FR-40: 系统必须只在两份快照都勾选的平台上计算四种结论。
- FR-41: 系统必须把对照快照没有、这次有的事件标为新出现。
- FR-42: 系统必须把两边都勾选的平台上来源条数变多，或多了这样一个平台的事件标为升温。
- FR-43: 系统必须把仍然采到、条数没有变多且没有 FR-42 所述新平台的事件标为还在。
- FR-44: 系统必须把对照快照有、这次在两边都勾选的平台上没采到的事件标为正在消退。
- FR-45: 系统必须把这次新勾选平台上的条目标为新加入的源，并且不得因此把已有事件标为升温。
- FR-46: 系统必须不得因为某平台这次被取消勾选，而把该平台上的旧事件标为正在消退。
- FR-47: 系统必须在某平台本次采集失败时保留其他平台的结果，并不得仅因该平台失败把事件标为正在消退。
- FR-48: 系统必须在全部平台采集失败时保留失败记录，且不得据此把旧事件标为正在消退。
- FR-49: 系统必须让简报中的每条结论至少带一条原链接，否则不写入简报。
- FR-50: 系统必须让正在消退的结论使用对照快照的链接。
- FR-51: 系统必须把每份简报写入 `简报/`，并在「概括」显示最新一份，在「总状况」显示其结论分组。
- FR-52: 系统必须允许已有快照的主题设定一个每日时间，或关闭晨报。
- FR-53: 系统必须在应用运行且到达晨报时间时自动采集，并按 FR-37 到 FR-46 生成晨报。
- FR-54: [Assumption] 系统必须在错过晨报时间后的下次启动补跑一次，记录实际采集时间，并仍对照该次晨报所属日期的前一个自然日。
- FR-55: 系统必须在用户点名整理且能解析出正文时，把笔记写入 `笔记/`。
- FR-56: 系统必须对能解析出正文的链接生成笔记，且不得把可解析平台写死为固定的三个站点。
- FR-57: 系统必须拒绝空链接和不能解析出正文的材料，并且不新增笔记。
- FR-58: 系统必须让该主题对话在回答时引用挂钩文件夹中的文件或快照中的原链接。
- FR-59: 系统必须在对话要求收集或修改平台时，先在调控面板列出动作，并在用户确认前不执行。
- FR-60: 系统必须在重启后仍能从挂钩文件夹读到主题、计划、快照、简报和笔记。

## Non-Goals

- 不做成企业舆情系统，不做声量大盘、情感大盘、账号权限和预警工单。
- 不提供「这次搜索不写入主题」的开关。每次收集、追踪、晨报都写入快照。
- 不由智能体在未经用户确认时启动收集或保存新的平台计划。
- 不在每次采集前重新确认整份计划。从对话发起的收集，只确认这一次动作。
- 不实现热度五因子打分。
- 不生成 RAG 五章节长文。
- 不导出 PDF，不通过 API、邮件、微信或其他外部渠道推送。
- 不把信息源写死，也不把未接入统一条目的平台假装成已经可勾选。
- 不把 OpenCLI 的写操作放进勾选清单。
- 不接受用户随意填写网址作为信息源。
- 不把某一个网站的热榜本身做成独立主题类型。热榜站点若能按关键词搜索并收成统一条目，只作为可勾选平台。
- 不把笔记计入来源条数，也不让笔记单独改写四种结论或「新加入的源」。
- 不把知识库做成文件夹之外的另一套资料库。
- 不把放进 `素材/` 的文件自动整理成笔记。
- 不做多用户、登录账号体系。各平台是否已登录，只读取 OpenCLI 的登录状态。
- 不要求第一版在应用内删除主题、快照或笔记，也不要求第一版提供完整的文件管理器。
- 不要求第一版为每个可搜索平台都做正文解析。

## Design Considerations

首页是主题卡片。新建后进入三区工作台，调控面板先停在计划确认。确认前，文件区可以看见已建好的空目录，总状况说明尚未收集，对话只解释计划。

确认后，工作面板默认停在「总状况」。调控面板放关键词、平台勾选、晨报时间、「现在收集」和「现在追踪」。概括页签阅读 `简报/` 里的最新短文。

没有快照时，「现在追踪」和晨报时间不可用。没有可对照快照时，总状况标题用「这次看到的事件」。手动追踪写明对照的上一份快照时间。晨报写明对照的前一个自然日；昨天没有快照时写明这一点。

有对照时，总状况按新出现、升温、还在、正在消退分组，并单独列出新加入的源。正在消退放对照快照里的链接。升温写清条数或新增平台。

文件区的「知识库」就是这个文件夹，不另设第四个资料页签。URL 保存在 `素材/`。笔记只在用户点名整理后出现在 `笔记/`。

没有视觉稿。三区在宽屏上并排。实现时优先保证总状况中的对比可读，不追求大盘式图表。

## Technical Considerations

- 仓库目前几乎是空的，只有说明这是智能体练习作品的 README。第一版需要自带可运行的 Web 应用，主题数据以挂钩的本地文件夹为准。
- 信息源清单在运行时用 OpenCLI 发现，不在代码里写死一份站点目录。某个命令能不能勾选，取决于它是否按关键词搜索，以及项目里是否已有把它收成统一条目的归一化。
- 已勾选且有直接接口的平台调用对应命令。已勾选但没有直接接口的平台才打开浏览器。登录状态用 OpenCLI 的登录查询读取。
- 关键词和预选平台的拆分、事件聚类、链接正文解析、主题对话使用模型。四种结论按 FR-40 到 FR-46 计算，不交给模型改写。
- 语义聚类要能把不同平台上的同一件事收成一个事件。验收至少使用夹具：三条同题不同平台的条目收成一个事件；两条标题明显不同的条目保持两个事件。
- 比较事件是否相同时，使用聚类结果，不要求链接相同。比较范围只包含两份快照都勾选且本次没有采集失败的平台。
- 主题对话读取挂钩文件夹中的文件。第一版不要求单独建立向量数据库；引用必须能对应到具体文件或原链接。
- [Assumption] 单用户本地运行。晨报调度依赖本机应用进程；进程不在时按 FR-54 补跑。
- 单点整理复用已有的正文解析能力。新平台要能整理成笔记，需要各自的解析。
- 平台采集受登录和页面改版影响。失败时按 FR-47、FR-48 降级，不把失败伪装成热度下降。

## Success Metrics

- 一次演示可以不借助手工改数据走完：新建、挂钩文件夹、改至少一个平台勾选、收集、再追踪、在总状况打开原链接。
- 演示中的简报文件出现在 `简报/`，快照文件出现在 `快照/`。
- 在对话里要求收集时，调控面板先列出动作；未确认前文件夹里不新增快照。
- 晨报夹具中，对照对象是前一个自然日的最后一份快照；昨天没有快照时不出现四种结论。
- 手动追踪夹具中，对照对象是上一份快照，简报写明该时间。
- 夹具覆盖新出现、升温、还在、正在消退、新加入的源，以及「取消勾选不算消退」「采集失败不算消退」。
- 抽查一份简报时，每条结论都有链接；不存在无链接结论。
- 计划未确认时，`快照/` 中没有新文件。
- 快照数为 0 时，追踪和晨报无法启动。

## Open Questions

- [Assumption] 错过设定时间后是否在下次启动补跑。PRD 暂按补跑写入 FR-54，对照日期仍取该次晨报所属日期的前一天。
- 应用技术栈尚未选择。行为要求与具体框架无关。
- 默认新建的文件夹放在哪个父目录，由实现时的系统文件夹选择决定。PRD 只要求用户能看见并改挂路径。
- 单点整理的正文粒度尚未规定是全文转写还是分段摘要。第一版只要笔记里有来源和可读正文。
- 聚类把两件不同的事并成一件，或把同一件事拆开时，第一版没有人工拆并界面。误并会直接影响条数结论。
- 运行时到底有多少 OpenCLI 平台能收成统一条目，取决于当时安装的适配器和已写的归一化，不在本 PRD 里报数量。
